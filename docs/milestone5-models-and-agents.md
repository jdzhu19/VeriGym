# Milestone 5 model clients and reference agents

Milestone 5 adds model-backed evaluation without changing the existing verifier contract or
starting broader benchmark, container, PPA, agent-framework, or RL work.

## Boundary and identity

A `ModelClient` accepts a versioned `ModelRequest` and returns a normalized `ModelResponse`.
It owns provider transport, finish-reason normalization, token-usage normalization, explicit
timeouts, and structured client errors. A model client does not decide which tools to run.

An `AgentAdapter` is the harness policy. `SingleTurnAgent` implements ChatEval submission;
`ReferenceReActAgent` implements a minimal strict-JSON action loop. The run manifest records
the model, agent harness, prompt policy, interaction mode, effective tool policy, budget,
runtime, suite release, and toolchain profile separately. Configuration fingerprints omit
credentials.

## ChatEval

`SingleTurnAgent` builds one deterministic prompt and calls its configured client once. It
accepts raw RTL or exactly one `verilog`, `systemverilog`, or `sv` fenced block. Empty output,
multiple blocks, surrounding prose, and non-RTL output are rejected as structured model-output
failures.

The environment's ChatEval policy exposes no tools. Even a manually supplied tool action is
denied before tool lookup or execution, is traced as a policy rejection, and consumes no tool
call budget. A valid final file is checked against the declared entrypoint and the existing
workspace write/size policy before verification.

## Reference ReAct AgentEval

`ReferenceReActAgent` accepts exactly one JSON object per response. Supported actions are
`tool_call`, `apply_patch`, `final`, and `abort`; unknown fields, malformed JSON, free-form shell
text, and direct file payloads are rejected. Parser feedback is visible and bounded, and the
episode terminates after the configured consecutive-invalid-action limit.

All accepted actions still pass through the environment. The task tool allowlist, verifier-only
visibility, safe paths, patch limits, turn/tool/model/token/wall-time budgets, and output limits
remain authoritative. The harness stores only visible messages and actions and neither requests
nor depends on hidden chain-of-thought. It is intentionally a small baseline, not a general or
production coding agent.

The `static-react-counter-good` fixture demonstrates this sequence:

1. Read `rtl/counter.v` through `file.read`.
2. Apply a unified diff through the safe patch tool.
3. Run the allowed visible Icarus simulation.
4. Submit final.

## Trace and privacy

Model requests, model responses, parsed actions, rejected actions, tool calls/results, patch
application, final submission, verification, budget updates, and termination are structured
events. Request IDs are generated by VeriGym. Provider usage remains unknown when the provider
does not report it; VeriGym does not estimate tokens.

Model-visible content is bounded before persistence. API keys, bearer headers, credential-bearing
URLs, and unrelated environment variables are never persisted. Hidden verifier source, commands,
and expected outputs are absent from prompts, observations, agent workspaces, traces, diffs, and
ordinary agent logs. Hidden assets are mounted only into a physically separate verifier session.

Replay reads the stored episode. `verigym replay <run-dir> --verify` reruns verifier-only stages
against the frozen task and candidate and never invokes or resets a model client.

## Optional OpenAI-compatible transport

Install the HTTP extra and configure an endpoint, provider model ID, and credential environment
variable name through explicit CLI options. Core imports and all tests work without the optional
HTTP package, an API key, or external network access. The client rejects missing configuration
with a structured error and uses separate connect, read, and overall request timeouts.

`LocalRuntime` remains `local_trusted`. The separate verifier session protects task visibility
for the committed trusted fixture, but it does not make local execution a security sandbox for
untrusted generated RTL.
